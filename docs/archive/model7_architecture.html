What changed

Model 7 is identical to model 6 in every way except one: the aggregation step. Instead of summing all neighbour embeddings uniformly, each neighbour's message is scaled by its violation depth before being added into the per-point context vector. Non-violating neighbours contribute exactly zero. Severely-violating neighbours dominate proportionally to their depth.

Same parameter count, same edge MLP, same output MLP, same loss, same dataset. One line of math — different inductive bias.

Why it matters

In model 6, a point with 49 legal neighbours and 1 severely-violating one averages the single meaningful signal across all 49 others — diluting it roughly 50×. Gradient flows through all N−1 edges equally regardless of physical relevance.

In model 7, the violating edge's signal is not diluted at all. A point with zero total violation gets agg = 0 exactly, which drives the output MLP toward zero displacement — the correct answer — with no learning required for legal points.

③ Edge MLP

Embedding Each Pair

Identical to model6. Weights shared across all N² pairs. Maps the 4-D edge feature to a 128-D embedding encoding the nature of each pairwise relationship.

④ Aggregate CHANGED

Violation-Weighted Sum

Each neighbour j's embedding is scaled by its violation depth before summing. Non-violating neighbours (depth=0) contribute exactly zero. A point with no violations at all gets agg = 0 → output MLP outputs ~0 → no displacement needed, no learning needed.

⑤ Output MLP

Predict Displacement

Identical to model6. Maps each point's 128-D context to a 2-D displacement. Added back to the noisy input via the skip connection. No output clamping.

The One Change

Aggregation — model6 vs model7

Everything outside this block is identical. Same parameters, same init, same loss.

# --- Zero out self-edges (i == j) ---
eye = torch.eye(N, dtype=torch.bool, device=x.device)
edge_emb  = edge_emb  * (~eye).unsqueeze(0).unsqueeze(-1)

- # model6 — uniform sum: all neighbours equally weighted
- agg = edge_emb.sum(dim=2)                              # (B, N, hidden_dim)

+ # model7 — violation-weighted sum
+ violation = violation * (~eye).unsqueeze(0).unsqueeze(-1)   # zero self-edges
+ viol_sum  = violation.sum(dim=2, keepdim=True)              # (B, N, 1, 1)
+ weights   = violation / (viol_sum + 1e-8)                   # (B, N, N, 1) sums to ~1 per i
+ agg       = (edge_emb * weights).sum(dim=2)                 # (B, N, hidden_dim)

Step 3 — Iterative Unrolling: Concrete Procedure

Model7.py is not modified. The entire change is in the training loop. The model is called identically each time — it simply receives updated point positions as input.

Current — K=1 (single pass)
noisy cloud x₀
    ↓
model7(x₀) → δ₀
    ↓
x₁ = x₀ + δ₀
loss = loss(x₀, x₁)
    ↓
backward → update
One gradient signal per batch. Model only ever sees freshly-noised clouds as input.
Unrolled — K=3
noisy cloud x₀
    ↓
model7(x₀) → δ₀  ← same model, same call
x₁ = x₀ + δ₀   loss₁ = loss(x₀, x₁)
x₁ = x₁.detach()  ← cut gradient tape
    ↓
model7(x₁) → δ₁  ← partially-corrected input
x₂ = x₁ + δ₁   loss₂ = loss(x₁, x₂)
x₂ = x₂.detach()
    ↓
model7(x₂) → δ₂
x₃ = x₂ + δ₂   loss₃ = loss(x₂, x₃)
    ↓
total = loss₁ + loss₂ + loss₃
backward → update
Three independent gradient signals. Steps 2 & 3 see partially-corrected clouds — a distribution never seen in K=1 training.
WHY .detach()?

Gradients flow only through one step's forward pass. The model learns "given any partially-corrected cloud, improve it" — a fixed-point iteration. Without detach: full BPTT, memory scales with K, vanishing gradients at K≥4.

WHY PER-STEP LOSS?

loss(x_current, x_next) measures displacement from that step's input, not from x₀. Each step is penalised for its own correction magnitude — the right signal for per-step efficiency rather than cumulative movement.

WHY MODEL7 SPECIFICALLY?

Model6's uniform displacement creates slack by accident — it doesn't need multiple passes because it shoves everything regardless. Model7's precision (median disp = 0.000×rd) is exactly the property that makes multi-pass refinement tractable without overshoot.
