Model Architecture — model9

Key Invariances
Translational: operates on x_i − x_j only — never raw positions.

Sparse attention: violation-weighted aggregation sets weight to zero for all non-violating neighbours — the correction signal comes only from pairs that actually break the constraint.
Edge MLP Input (4D)
rel_pos — relative position vector (2D)
dist — Euclidean distance (1D)
violation — relu(rd − dist) (1D)

Each of the N×N edges is embedded independently, then violation-weighted-summed per destination node.
Output Clamp
Δx = tanh(raw) × max_disp

Hard displacement ceiling per step. max_disp = 1.2 × rd. Prevents cascade failures in packed geometry where a single over-correction creates new violations.
Iterative Unrolling
Trained with K=3 steps per batch. Both K=1 (deploy) and K=3 (train) evaluated at every checkpoint. Each step re-computes all edges on the updated cloud.

Architecture Evolution

Each model is a minimal change from the previous — one hypothesis tested at a time. Sparse runs: N=50, rd=0.05. Packed runs: rd=0.05, packedness varies.

6
model6 — Uniform-push baseline Architecture
Aggregates messages from all N−1 neighbours equally. Fixes violations but moves every point — legal or not. Sparse geometry has slack so illegal pairs reach near-zero, but mean nearest-neighbour drifts +31% above natural at ×5 passes. In packed geometry this would cascade new violations.
Edge input: rel_pos + dist (3D) · 2-layer MLP · no clamping
~91%K=1 ill. pairs reduced
+31%NN drift at ×5
7
model7 — Violation-weighted aggregation Architecture
Problem: uniform sum over N−1 neighbours dilutes the violating signal ~50×.

Fix: weight each neighbour's message by its violation depth — non-violating neighbours contribute exactly zero. Corrections become surgical: median displacement = 0.000×rd. The model moves only points that need moving.

Trained K=3 with principled lambda (λ₁=1/rd, λ₂=λ₁/(N−1)/10).
+48% surgical efficiency · exposes multi-point cluster ceiling
65.6%K=1 viol. reduction
87.9%K=3 viol. reduction
85%K=1 efficiency
9
model9 — Deeper edge MLP + output clamping Architecture Production
Problem 1: 2-layer edge MLP undersells cluster geometry — 3+ mutually-violating points form patterns a shallower MLP can't represent.

Problem 2: packed training showed unbounded displacements up to 3.4×rd, cascading new violations.

Fix: 3-layer edge MLP (4→h→h→h) + tanh(·)×max_disp clamp. Max displacement drops to 0.96×rd. model8 (GELU only) is an intermediate step subsumed by model9.
Stable packed training. Production architecture.

Up Next — Real Data Benchmark

Step 10 · Real Data

The decisive test. Everything trained so far used synthetic Poisson disk data. Real data has N≈2500 on a toroidal domain with unknown noise distribution.

11a — Sparse radius graph + MIC No retraining
  • Idea: model is purely local — violation-weighted agg already ignores pairs beyond rd
  • Build radius graph with cutoff 2×rd: ~10–20 edges/point at N=2500, ~13 MB vs 3.2 GB dense
  • MIC at inference: rel_pos -= round(rel_pos) makes cross-boundary violations look like interior ones — no architectural change
  • Post-correction mod 1.0 wraps positions back to [0,1]²
  • One new file using scatter_add. No new training.
11b — 5×5 domain tiling N=100 models ready
  • Idea: partition [0,1]² into 25 cells of ~100 pts each, apply small model in parallel
  • Extend each cell by rd halo — cross-boundary violations seen by at least one cell
  • Feed cells in absolute coordinate space — do not rescale to [0,1]², that would inflate rd
  • Apply updates to core points only, discard halo updates
  • p=0.50 model (rd=0.076, N=100) is the deployment target
Evaluation metrics No ground truth
  • viol/cloud before vs after — primary metric; model6 vs model9 decisive test
  • NN drift — mean nearest-neighbour / rd must stay close to 1.0 after correction
  • Cascade check — new violations introduced vs resolved; net = resolved − introduced
  • Zero-violation stability — clean real clouds must produce near-zero displacement
  • rd inference — estimate from 5th-percentile NN distance on clean examples
Hypothesis to resolve Open question
  • model6's global push cascades violations in packed geometry — expected to fail on real data
  • model9's violation-weighted approach should confine corrections to violating pairs only
  • Unknown: real data noise distribution vs synthetic training noise
  • Unknown: whether toroidal boundary effects dominate (favours 11a MIC approach)
  • Output: comparison table + visualisations in analysis/eval_real.py
Model selection for real data: use model9 hd128_d3 weights from the p=0.90 capacity grid run for approach 11a (it was trained at the hardest density). For approach 11b, use the p=0.50 N=100 model (rd=0.076, N_actual=100, K=3: 85.1% on validation).

Conclusions

What works

Violation-weighted aggregation
The single most impactful change (+48% efficiency). Non-violating neighbours contributing zero is the correct inductive bias — the model learns where to push, not just where to look.
K=3 iterative unrolling
Essential for packed geometry. At p=0.90, K=3 advantage over K=1 is +24pp. Multi-point clusters require sequential resolution — each step opens space for the next.
Output clamping (tanh × max_disp)
Prevents cascade failures in dense clouds. Max displacement dropped from 3.4×rd to 0.96×rd, enabling stable packed training without sacrificing reduction quality.
Small model generalises well
model9 hd128_d3 at 51K params matches 200K–268K variants on fair 200-cloud evaluation. The task is sufficiently local that extra capacity doesn't help — and is also more surgical (lowest displacement/rd).

What didn't pan out

Width scaling (hd256, hd512)
No meaningful improvement over hd128 on fair evaluation. hd512 is 8× slower with no advantage even at 25% training. The bottleneck is not representational capacity.
Depth scaling (edge_depth=4)
Appeared to help on small validation sets, did not hold up on 200-cloud evaluation. Larger depth also uses more displacement per correction step.
Self-feature (model10)
+5pp K=1 on sparse N=50, reversed in packed regime. 15.5 vs 17.9 violations/cloud at K=3 — marginal, at the cost of 35% more displacement and much higher brittleness.
19-cloud validation sets
Too small to discriminate real gains from noise. Produced consistent false positives throughout the capacity grid — always showed larger models winning. All future evaluations: validation_size=200.
